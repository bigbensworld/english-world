# 英语世界：零成本视觉实施与验收标准

> 版本：v1.0 · 2026-10-07
> 目标：在不购买美术资源、不引入运行时依赖的前提下，把 demo 做到“画面精美、人物灵动可爱”，并建立可以逐项验收的发布门槛。

## 一、执行结论

采用 **CSS 动效 + 本地 Fluent Emoji 3D 图标 + 数据驱动场景主题 + CSS 吉祥物状态机**。

暂不引入：Three.js、PixiJS、Lottie、GSAP、付费字体、付费插画、在线音效服务和后端。

核心原则：

1. 精美靠统一视觉系统，而不是堆素材。
2. 灵动靠短促、分层、可控的反馈动画，而不是全屏持续晃动。
3. 可爱靠角色状态和反馈文案，不靠复杂建模。
4. 所有资源本地化，加载失败可降级。
5. 动画必须服从可读性、操作效率和移动端性能。

---

## 二、分阶段实施步骤

### 阶段 0：冻结视觉基线

**目标：**先统一规则，再继续加内容。

**修改文件：**

- `english-world/style.css`
- `english-world/data.js`
- `english-world/game.js`
- `english-world/index.html`

**执行：**

- 统一背景、主色、奖励色、错误色和场景色为 CSS 变量。
- 统一卡片、按钮、弹窗的圆角、边框和阴影层级。
- 保持咖啡店暖棕、超市嫩绿的主题差异。
- 约束动画只优先使用 `transform`、`opacity`、`filter`。
- 为场景保留数据字段：`theme`、`accent`、`accentSoft`、`deco`、`deco2`。

**完成条件：**同类组件样式一致；新增场景只需增加主题字段，不复制整套 CSS。

### 阶段 1：升级场景地图

**修改文件：**

- `style.css`
- `game.js`
- `data.js`

**执行：**

- 场景卡片增加封面渐变、柔和光晕和主题装饰。
- hover 时卡片轻微上移，代表图标轻微放大/旋转。
- 锁定场景使用低饱和遮罩和解锁提示，不直接把整张卡片做成不可读的半透明。
- 地图进入采用错峰弹入，总延迟控制在 600ms 内。
- 点击场景时提供明确的按下反馈。

**完成条件：**桌面端和手机端无横向溢出，3 秒内能看懂当前场景和主要入口。

### 阶段 2：升级物品探索反馈

**修改文件：**

- `style.css`
- `game.js`

**执行：**

- 未收集物品：错峰轻微浮动，不全部同步运动。
- hover：图标上浮/摇摆；触摸端不依赖 hover。
- 首次收集：图标放大、边框变绿、出现勾选和星光、词汇 HUD 有轻微反馈。
- 重复查看：保留词卡，但不重复播放“新词收集”特效。
- 词卡内容分层出现：图片、单词、音标、中文、例句、发音按钮。
- 图片加载失败时继续显示原 emoji 降级。

**完成条件：**用户能明确区分“首次收集”和“重复查看”；每次反馈不阻塞操作超过 700ms。

### 阶段 3：完成吉祥物状态机

**修改文件：**

- `style.css`
- `game.js`
- 必要时 `index.html`

**状态：**

| 状态 | 触发 | 视觉反馈 |
|---|---|---|
| `idle` | 默认 | 呼吸、偶尔眨眼 |
| `happy` | 新词收集、答对 | 弹跳、腮红增强、开心嘴型 |
| `thinking` | 题目出现、等待选择 | 轻微摆动或思考动作 |
| `sad` | 答错 | 短暂下沉/摇头，随后回到 idle |

**执行：**

- 通过 class 切换状态，不复制多个角色 DOM。
- 角色动作与文字、颜色或图标同时表达关键信息。
- 角色不覆盖词卡、答案和底部按钮。
- 角色默认安静，只有事件发生时才使用明显动作。

**完成条件：**至少 `idle/happy/sad` 三种状态可验证；连续快速点击不造成动画堆叠或状态错乱。

### 阶段 4：升级小游戏奖励链路

**修改文件：**

- `game.js`
- `style.css`

**答对：**

1. 选项变绿并轻微放大。
2. 显示 `+1` 或星光反馈。
3. 吉祥物切换 `happy`。
4. 发音或鼓励语可用时播放；不可用时文字仍完整。
5. 约 900ms 后进入下一题。

**答错：**

1. 当前选项摇摆。
2. 正确选项高亮。
3. 吉祥物切换 `thinking` 或 `sad`。
4. 显示正确答案和简短提示。
5. 约 1400ms 后允许继续。

**结算：**

- 依分数显示 1~3 个星级反馈。
- 金币数字逐步跳入。
- 达到解锁条件时显示下一场景提示。
- 支持再来一局和返回探索。

**完成条件：**答对、答错、结算三种状态视觉差异明确；连续完成 10 局无状态污染。

### 阶段 5：移动端、无障碍和性能收口

**修改文件：**

- `index.html`
- `style.css`
- `game.js`
- `test.js`

**执行：**

- 主要触控目标至少约 44×44 CSS px。
- 主要交互使用真实 button/可聚焦元素。
- 图片提供准确 `alt`，装饰图隐藏或空 alt。
- 增加清晰的 `:focus-visible` 样式。
- 动态结果使用合理的 `aria-live="polite"`。
- 支持 `prefers-reduced-motion: reduce`。
- 场景卡、物品格、小游戏选项在 320px 宽度下仍可用。
- 补充图标路径、图片降级、角色状态和核心流程的自动回归断言。

**完成条件：**核心流程在桌面、手机、键盘和减少动画模式下都能完成。

## 三、文件职责

| 文件/目录 | 职责 | 本阶段动作 |
|---|---|---|
| `index.html` | 页面骨架、按钮、弹窗、语义 | 补语义、可访问名称和 live region |
| `style.css` | 视觉变量、布局、动画、角色状态 | 主要视觉升级文件 |
| `game.js` | 状态、渲染、交互、TTS、动效触发 | 增加角色状态和反馈触发 |
| `data.js` | 场景、物品、主题、台词 | 增加主题字段和受控文案 |
| `assets/icons/*.png` | 本地 Fluent Emoji 3D 图标 | 继续复用，不新增采购 |
| `assets/licenses/*` | 来源、commit、许可证快照 | 保留并在正式版提供入口 |
| `test.js` | 无头核心流程测试 | 增加状态和降级断言 |

## 四、P0/P1/P2 验收标准

### P0：阻断发布，必须全部通过

#### 视觉与角色

- [ ] 在 `1366×768`、`1440×900`、`390×844`、`768×1024` 下首屏不裁切。
- [ ] 无横向滚动条：`document.documentElement.scrollWidth <= window.innerWidth`。
- [ ] 3 秒内能识别当前场景、角色/可操作对象和主要操作。
- [ ] 无破图、乱码、空白核心区域和文字遮挡。
- [ ] 角色不遮挡按钮、词卡、答案和提示。
- [ ] 点击/触摸后 100~300ms 内开始反馈。
- [ ] 连续快速点击不会造成动画堆叠、状态错乱或页面冻结。

#### 核心玩法

- [ ] 可完成“进入场景 → 点击物品 → 查看词卡 → 收集词汇 → 开始小游戏 → 正确/错误反馈 → 结算/返回”。
- [ ] 正确、错误、完成状态至少同时有两种反馈方式。
- [ ] 可返回、重试和重置，不需要刷新页面恢复。
- [ ] 连续完成 10 轮/局不出现状态污染。
- [ ] 英文标题、按钮、提示和答案无明显拼写、语法和大小写错误。
- [ ] TTS 不可用时，文字、音标、例句和游戏结果仍可用。

#### 移动端与无障碍

- [ ] 375×667、390×844、412×915、768×1024 均可完成核心流程。
- [ ] 主要触控目标不小于约 44×44 CSS px。
- [ ] 核心操作不依赖 hover。
- [ ] 键盘可访问主要控件，焦点清晰可见。
- [ ] 关键动态反馈可通过文本感知。
- [ ] `prefers-reduced-motion: reduce` 生效。
- [ ] 普通文字对比度达到 WCAG AA，且颜色不是唯一反馈。

#### 性能与资源

- [ ] 核心流程 Console 无 error、未处理 rejection 和新增 404。
- [ ] 页面 3 秒内可进行主要操作。
- [ ] 核心动画不持续低于约 30 FPS。
- [ ] 连续操作 5 分钟或 20 轮不冻结、不明显泄漏。
- [ ] 所有图标均来自本地资源，图片失败有 emoji 降级。
- [ ] 每个第三方资源都有来源、版本和许可证记录。
- [ ] 不包含 API key、token、密码或未知远程脚本。

### P1：发布前应清零

- [ ] 场景主题通过数据字段驱动，新增场景无需复制整套 CSS。
- [ ] 首屏、场景、词卡、小游戏、结算页视觉规则统一。
- [ ] 吉祥物至少支持 `idle/happy/sad` 三种状态，且状态与事件同步。
- [ ] 角色、物品、小游戏动画时长通常在 150~500ms，最长不超过 700ms。
- [ ] 锁定、解锁、收集、再来一局均有明确反馈。
- [ ] 物品、场景和按钮有可见的键盘焦点样式。
- [ ] 页面标题、标题层级、按钮名称和图片 alt 完整。
- [ ] Chrome、Safari、Firefox、Edge 至少各完成一次核心流程。
- [ ] iOS Safari 和 Android Chrome 至少各完成一次核心流程。
- [ ] Lighthouse Performance/Accessibility 达到 85+；理想 90+。
- [ ] 建立资源清单和已知问题清单。

### P2：后续优化

- [ ] 固定视口截图回归，关键位置偏差控制在约 4px 内。
- [ ] LCP ≤ 2.5s、CLS ≤ 0.1、INP ≤ 200ms。
- [ ] 增加高对比度、大字体、深色模式适配。
- [ ] 增加角色动作轻随机性，但不影响可预测性。
- [ ] 增加自动化视觉回归和更多低端设备验证。
- [ ] 增加站内资源来源与许可证页面。

## 五、建议验收顺序

1. 先跑现有 `node test.js`，确认核心逻辑基线。
2. 完成阶段 0~2 后，验证地图、物品、词卡和图片降级。
3. 完成阶段 3 后，逐一触发 idle、收集、答对、答错、结算状态。
4. 完成阶段 4 后，连续完成 10 局并清空/恢复 localStorage。
5. 完成阶段 5 后，验证四种视口、键盘、减少动画和 Console。
6. 最后进行跨浏览器、弱网/离线和资源许可证检查。

**发布门槛：P0 全部通过；P1 清零或明确记录豁免；P2 形成后续迭代清单。**
