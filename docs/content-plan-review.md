
审查结论：原 v1.0 方向正确，但不能直接按“全量自动生产、全部可商用、4 周 20 场景”执行。主要问题已在 v1.1 修正：

- 先做数据审计：CEFR-J 的字段/数量/主题域必须按锁定 CSV 实测；ECDICT 的默认基础 CSV 是约 76 万词条，不能直接写 340 万。
- 许可证分层：数据、代码、TTS 服务、生成内容、图标资产分别建档，不能因 GitHub 仓库有 MIT/GPL 就推导数据或音频自动可商用。
- 例句质量：Tatoeba 逐句归因；AI 输出只视为候选草稿，必须人工审校、相似度检查和安全筛查。
- 量产模型：增加 sense/POS/CEFR/topic/source/license/audio/review 等字段，避免后续无法追溯和修订。
- 产能修正：先用 2~3 个场景测基准，不再承诺每场景 1 小时；原型期按每场景 0.5~1.5 个工作日规划更稳妥。
- 执行顺序：先完成咖啡店与超市的真实内容重制，跑通审计、选词、富化、例句、音频、图标、验收闭环，再决定是否批量扩展到 20 场景。
